# 演出节点数据采集与转换

## 基本规则

Excel 的“演出场次”工作表采用“一行一个具体场次”，但地图上的节点可以包含多场。同一轮巡演在同一个场馆的多场演出填写多行，并使用**相同的节点 ID**；转换脚本会把这些行合并成一个节点，其下保存多个 `sessions`。

不要把作品、制作版本和具体场次混为一条记录：

```text
作品：RENT
制作版本：RENT 2026 中国巡演版
节点：RENT 2026 中国巡演版 · 北京天桥艺术中心站
场次：2026-03-21 14:00、2026-03-21 19:30、……
```

## ID 与扩展策略

- `节点ID` 是稳定的业务标识。同一制作版本、同一场馆的一组演出共用一个 ID；发布后不要因标题改名而修改。
- 推荐格式：`evt-国家代码-城市-制作版本-场馆`；不要把日期或时间放入节点 ID。
- 经常使用、需要筛选的属性应新增正式列，并同步修改转换脚本。
- 临时或少量属性放入“扩展信息JSON”，例如 `{"字幕语言":"中文","谢幕场":true}`。
- 不要把核心字段长期塞入扩展 JSON；使用频率稳定后应升级为正式字段。
- `schemaVersion` 用于未来迁移。改变 JSON 字段语义时递增版本并保留迁移脚本。

## 转换

项目不需要安装第三方 Python 包：

```bash
python tools/convert_events.py outputs/event-data-pipeline/event-earth-events-template.xlsx
```

默认输出：

```text
core/data/generated/events.json
```

指定输出：

```bash
python tools/convert_events.py input.xlsx -o output/events.json
```

脚本会校验必填字段、分类、日期、经纬度、同节点字段一致性、重复场次以及扩展 JSON，并同时输出：

- `entities`：规范化的作品、制作版本、场馆和具体场次；
- `nodes`：地图前端可直接消费的扁平节点；
- `schemaVersion`：数据结构版本。

## 推荐协作流程

1. 负责人复制一个空白模板给资料整理者。
2. 整理者只编辑“演出场次”，并参考“填写说明”和下拉选项。
3. 收回文件后运行转换脚本；有错误则按行号退回修正。
4. 检查来源链接和重复节点，再提交生成的 JSON。
5. 后续接入数据库时，直接使用 `entities` 层，不必从扁平节点反推关系。
